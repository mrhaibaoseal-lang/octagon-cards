## 2. 橫版版面（對戰頁）

以 iPhone 844×390pt 為設計基準，要適應安全區域與較小機型。

- **八角籠 `SpriteView` 滿版當背景**，不再因播放而改變尺寸；SwiftUI 介面疊在上面。
- **上方轉播列**：左右對稱的雙方血條（頭／身／腿＋體力、勢能）、中央回合數、回合進度與局勢。
- **下方手牌**：5 張扇形手牌，點選放大、往上拖＝出牌；播放交手時滑出畫面，人物與翻牌不被遮擋。
- **左下**：抽牌／棄牌數、上一手、戰報。**右下**：速度與選單（算式、重現碼、重開、回選角收進選單）。
- 畫面上要保留 Rocked／深鎖／流血警示。

人物顯示高度約 200pt（邏輯 65px ×3）。站位要避開手牌，或在選牌時讓手牌只露出上半部。

## 3. 戰鬥人物：小型 Q 版（共用身體模板＋官方照的頭）

### 3.1 為什麼改成這樣

P6-2 用 Vision 切官方照的軀幹與手臂，32 位只有 20 位可用（門檻 28），主因是手肘位置錯。部分官方照還抱著冠軍腰帶擋住軀幹（如 Gane、Volkanovski），照片貼圖本來就不可靠。使用者接受「小一點、身體共用、刺青大概就好」，因此**身體不再用照片，也不再用 Vision 找身體關節**。

原型結果（程式在 `pipeline/chibi_proto/`，輸出不進 repo）：
- 32 位都能自動取頭，排成一張圖目視，都是完整的頭，也認得出人（只看過這張 idle 圖，未在手機上看）。
- P6-2 判不可用的選手也能做出所有動作，因為身體不依賴他們的照片。

### 3.2 尺寸

| 項目 | 規格 |
|---|---|
| 全身 | 邏輯約 65px 高，頭約 25px（約 38%） |
| 顯示 | 最近鄰放大 ×3，約 200pt 高；八角籠的 844×390 版面放得下 |
| 細節 | 身體只有 3 階膚色（基底、陰影 ×0.72、高光 ×1.12）、1px 描邊，肌肉只留胸線與腹線 |

使用者的參考圖是概念圖，實際約 200px 高，細節在 65px 做不出來。這裡取它的比例、站姿和動作清單，不追它的細節。

### 3.3 每位選手的差異

| 部分 | 來源 | 方式 |
|---|---|---|
| 頭 | 官方全身照（解析度通常比大頭照高，Jones 的大頭照還切到頭頂） | 用透明通道的寬度變化找頭頂與脖子，下緣用橢圓遮罩修圓，縮小後量化 18 色並描邊。手機端可再用 Vision 臉部偵測當檢查 |
| 膚色 | **外觀資料表** | 自動取樣不可靠：臉中央會取到高光，軀幹會取到腰帶或刺青。原型裡 Gane、Jones 的身體明顯比臉淺 |
| 刺青 | **外觀資料表** | 分 6 區（胸、腹、左右上臂、左右前臂），每區濃度 0–3，可選墨色偏色。用雜訊團塊畫出「大概有刺青」，座標綁在部位上，動作時不會閃爍 |
| 體型 | **外觀資料表** | 細／中／壯，調整肩寬與四肢粗細 |
| 短褲 | 全身照底部取色，資料表可覆寫 | 去掉接近膚色的像素後取中位數；原型有 3 位取不到（改用深色）、部分明顯偏掉（如 Jones 底部是腿）。需要時用資料表修正 |
| 手套、手綁帶 | 共用 | 不分人 |

外觀資料表：App 層讀取的 `data/fighter_looks.json`，不動 `OctagonCore`，不含照片。32 位由 agent 看過官方照後填第一版，使用者再修正。不在表上的選手走預設值：刺青 0、中體型、膚色用臉部低亮度取樣。

### 3.4 動作影格

**不旋轉貼圖**，而是依姿勢表在邏輯解析度直接畫出每一格，低解析度下線條才乾淨。原型做法：左右肢以關節角度算出位置，每個四肢是帶錐度的膠囊形，一條手臂或腿共用一圈描邊。

第一批動作：待機（2 格）、刺拳、後手直拳、踢、受擊、倒地。姿勢數值在 `pipeline/chibi_proto/proto.py` 的 `POSES`，**踢和倒地還不好看，要再調**。

人物面向右，右側選手整張鏡像。頭是正面照，身體是斜側面，這是已接受的取捨。地面戰尚未設計，實作前先維持現有呈現。

### 3.5 已知未解

1. **身體美術仍是程式草稿**：比例可用，但比參考圖粗糙。P6-3 先調產生器；不夠好再用一次性共用素材（`RULES.md` §2）當參考。
2. **臉和身體的質感差**：頭是照片縮圖，身體是平塗，放在一起略有落差，要實機看。
3. **地面戰**：雙人姿勢如何做，尚未設計。

### 3.6 退路

取頭失敗或無官方照時，用量級剪影的頭配同一副身體（`RULES.md` §4.2）。身體不依賴照片，所以所有選手都有完整動作。
